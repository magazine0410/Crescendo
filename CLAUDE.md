# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Crescendo is a Tauri 2 + Svelte 5 music player for Linux that replicates the foobar2000 **Eole** theme (dark mode). It is built for a ~136k-track, FLAC-heavy library on an HDD — every design decision below follows from "never make the UI wait on 136k rows".

The visual source of truth is the original theme in `reference/Ottodix-Eole-foobar-theme-ea6744c/` — colors and layout constants were extracted from `themes/eole/js/JStheme_common.js` into `src/lib/styles/tokens.css`. When adjusting the look, check the reference theme (and its `preview.png`) before inventing values. Priority order for appearance decisions: theme files > user's screenshots > written specs.

**Icons are the exception**: they are inline **Lucide** SVGs (see *Frontend > icons* below), not theme sprites — the Eole PNG glyphs were removed for licensing reasons, so don't reach for `/eole/controls/*.png`. Colors and layout still follow the theme.

## Commands

```bash
npm run tauri dev        # run the real desktop app (rebuilds Rust on change)
npm run dev              # frontend only at :1420 — runs against src/lib/mock.ts, no Rust needed
npm run check            # svelte-check (type-check the frontend)
npm run tauri build      # release bundles → target/release/bundle/{rpm,deb}

cargo test -p crescendo-core                          # all core tests
cargo test -p crescendo-core --test search_test       # one test file
cargo test -p crescendo-core --test search_test free_text_japanese  # one test

# Headless harnesses (run against real files / the real DB):
cargo run --release -p crescendo-core --example smoke -- <music-dir> <db-path>   # scan + search + art
cargo run -p crescendo --example play_test -- <file>...                          # GStreamer playback + gapless
cargo run --release -p crescendo-core --example m3u_art_test -- <db> <m3u> <cache-dir>
```

Runtime data: DB at `~/.local/share/crescendo/library.db` (SQLite WAL — safe to open with a second connection while the app runs), thumbnails at `~/.cache/crescendo/thumbs/`.

## Architecture

**Two Rust crates, deliberately split.** `crates/core` (crescendo-core) holds everything with no UI dependency: DB/schema/queries, scanner, search compiler, play-queue logic, m3u, cover-art resolution, Last.fm client. It builds and tests without webkit2gtk/GStreamer headers. `src-tauri` is a thin shell: the GStreamer player thread, `#[tauri::command]` wrappers (in `src/commands/`, no logic of their own), the `crescendo-art://` protocol handler, and window management. Put new logic in core unless it needs tauri or gstreamer types.

**The frontend never receives the whole library.** Views get counts and fetch windowed slices through the `tracks_range` Tauri command, or bounded sets (albums for a selection, one playlist). Playback starts by sending a **context descriptor** (`PlayContext`: album / playlist / library_view / value_tracks) plus a start index; the Tauri command re-resolves it to an ordered id list (`Db::resolve_context_with_projection`, while holding the projection guard that validated the descriptor's revision) using the same SQL the view used, and the player thread receives only concrete ids. Track-id lists never cross IPC. The `*_exact` query wrappers in `queries.rs` deliberately skip plugin transforms and exist only for tests, examples, and headless harnesses; application commands must use the corresponding `*_with_plan` methods while holding a projection guard.

**Player** (`src-tauri/src/player/mod.rs`): one thread owns a `playbin3`; commands arrive via mpsc `Cmd`, state flows out as `player:state` / `player:position` (250 ms tick) Tauri events, mirrored into a shared `Mutex<PlayerState>` for `player_get_state`. Gapless works by setting the next uri inside GStreamer's `about-to-finish` callback — which calls `PlayQueue::advance()` *early*, so the queue is already advanced when `StreamStart` fires. Ordering semantics live in `crescendo_core::playqueue` (pure, unit-tested): ad-hoc queue always preempts the context (foobar behavior), shuffle is a permuted walk order that keeps the current track, repeat cycles off→all→one. `queue_add` accepts already resolved track IDs, so an active context and ad-hoc queue cannot be reinterpreted by a later facet-projection change.

**Scanner** (`crates/core/src/scanner/`): walker thread (extension whitelist) → mtime/size diff against an in-memory map of known files (unchanged files never get their tags read — this is why rescans take seconds) → 4 lofty reader threads (HDD-tuned, `scan_threads` pref) → single writer batching 1000/txn. Unreadable tags fall back to filename-only rows (relaxed lofty parsing first). After every scan `albums.rs::rebuild` regenerates the albums table in one GROUP BY pass, upserting on a normalized `(albumartist-or-artist, album)` key so album ids — and therefore the thumbnail cache — stay stable.

**Search** (`crates/core/src/search/`): hand-rolled recursive-descent parser for Quod Libet syntax → AST → SQL WHERE fragment with *anonymous* `?` params only (queries.rs appends numbered params after it — keep that invariant). SQLite's LIKE/lower() are ASCII-only, so matching goes through Rust UDFs (`ulower`, `ucontains`, `regexp`) registered per connection; free text hits `search_blob`, which is Rust-lowercased at insert time. The library is heavily Japanese-tagged — test any matching change against non-ASCII (see `tests/search_test.rs`).

**Cover art**: no image blobs in the DB. `albums.cover_source` caches the resolution (`folder:<path>` or `embedded:<track_id>`); thumbnails generate lazily on first request through the `crescendo-art://` protocol (semaphore-bounded), so the virtualized album wall only ever generates what's visible.

**Play history**: `record_play` (called by the player once more than half a track has been heard) writes one dated row per play into `play_history` — epoch plus the *local* calendar year/month/day — and, in the same transaction, bumps `tracks.play_count` and refreshes the `tracks.last_played` cache. Nothing reading the library joins the history table: the `plays` search tag and the `%playcount%` browse filter read `play_count`, and the `%lastplayed%` browse filter plus the Last-played sort read `last_played`, so a 136k-row view never pays for a join. The filter's spans are *rolling day counts* (`last_played_bucket` in queries.rs — today / 7 / 30 / 365 days / longer / never), computed from local midnights so the time of day and DST cannot move a play across an edge. Tracks are never deleted (the scanner only sets `missing = 1`), so history rows never orphan.

**Romanized display**: the library carries `titlesort`/`artistsort`/`albumartistsort` tags with romaji for Japanese names. Wherever a title or artist renders, use the `display*` helpers in `src/lib/format.ts` (never raw `t.title`/`t.artist`): they substitute the sort tag when the original contains CJK and the sort tag exists, and are a no-op otherwise. The substitution is gated on the `prefer_romanized` pref (default on, Settings > "Prefer romanized names where available"); the frontend format helpers read the live pref, while backend facet identity and ordering read the same value from `PluginManager`'s guarded `ProjectionSnapshot`. `prefs_set` routes this preference through `PluginManager::set_prefer_romanized`, which persists it and publishes a new projection revision; the frontend applies it through `library.changeProjection`, invalidating old requests and rebuilding the view before interaction resumes. Tauri library commands pass the guard's value into `FacetPlan` and the `*_with_plan` queries, and playback uses `Db::resolve_context_with_projection` under that same guard, so visible labels, row order, and context indices stay aligned. The headless `*_exact` wrappers instead read `Db::prefer_romanized()` directly because they have no plugin registry. `browse_values_with_plan` returns named `BrowseValue` rows; Last.fm queries keep the raw names.

**Frontend** (`src/lib/`): Svelte 5 runes stores in `stores/*.svelte.ts`; `api.ts` routes `call()` to real IPC or to `mock.ts` when not in Tauri — keep mock.ts in sync when adding commands so `npm run dev` stays useful. `events.ts` bridges Tauri events into stores. Virtualization is hand-rolled (`virtual/VirtualList.svelte` with prefix-sum offsets for mixed-height rows, `VirtualGrid.svelte` on top of it); mixed-height lists like the grouped playlist view pass an `itemHeight(index)` function. Panel sizes persist via `prefs.setLayout` into the backend `prefs` table (the only settings store — no tauri-plugin-store).

**Plugins** (`crates/core/src/plugins/`): local `.crescendo-plugin` ZIP packages are copied into a private staging operation, validated with strict path/size/schema limits, and promoted under `<data>/plugins/installed/`. The database stores desired state, deferred update/uninstall journals, namespaced setting values, capability grants, and Wasm namespaced storage; package metadata stays authoritative in `manifest.json`. `PluginManager` builds an immutable loaded contribution registry at startup, recovers journalled operations before scanning, and enters a one-run safe mode after an incomplete startup. First installs are immediately visible but disabled; loaded-set changes apply after restart. Live projection settings publish through a guarded `ProjectionSnapshot` revision: every dependent library query and `PlayContext` carries that revision, stale requests are rejected, and contexts are resolved to concrete IDs before reaching the player thread. Declarative v1 supports host-rendered settings, the trusted `text.first_segment` facet transform, and `library.filter` toggle controls; it never executes plugin code or SQL. Passive assets are loaded only as bounded bytes through `PluginManager::load_asset(plugin_id, asset_id)` for a plugin in the immutable loaded set — never by exposing package paths or serving files directly to a webview. `cargo run -p crescendo-core --bin crescendo-plugin -- {validate,pack}` is the supported package tool; it shares the runtime validation path, produces deterministic archives, and prints SHA-256. The versioned schema and authoring/compatibility/operations guides live under `plugin-sdk/` and `docs/plugins/`. The canonical source and private migration package for `dev.crescendo.primary-grouping` live under `plugins/` and `src-tauri/resources/plugins/`, while the release workflow attaches a freshly packed copy to each GitHub release. Management commands are main-window-only and must stay synchronized across `generate_handler!`, `build.rs`'s `COMMANDS`, `capabilities/main.json`, and `mock.ts`; the build also asserts that plugin permissions never enter the About or shared cover-window capability.

**Wasm plugins** (`crates/core/src/plugins/wasm/`): a `kind: "wasm"` package's `module.wasm` is a Component Model binary built against the versioned WIT world in `plugin-sdk/wit/` (runtime API `WASM_API_VERSION`, checked against `api_version` in the manifest). One dedicated runtime thread owns a Wasmtime engine and one isolated component per loaded Wasm plugin; no WASI is linked, only the `crescendo:host` interfaces (live `settings` + bounded `log`; `storage` and windowed `library` pages are permission-gated per call). Plugin identity lives in the store data — host imports never accept a caller-supplied plugin id. Guest work is bounded by a 64 MiB memory limiter, per-call fuel, an epoch deadline (1 ms ticker thread), a bounded request queue, and 1 MiB invoke input/output. Capability grants are user-approved per exact package (identity, version, hash) and stored in `plugin_grants`; an update voids them until re-approved, and enabling without an approval is rejected. The failure policy: trapped/timed-out commands fail cleanly, three session failures mark the plugin unhealthy, and a second startup-init failure persists `desired_enabled = false` (auto-disable). `plugin_invoke(plugin_id, command_id, input)` is the only dispatch path and reaches only commands declared in the manifest's `contributes.commands`. The canonical example is `plugins/dev.crescendo.wasm-demo/` (build with `rustup target add wasm32-unknown-unknown` + `wasm-tools`, `./build.sh`); its built component is committed at `crates/core/tests/fixtures/wasm-demo-module.wasm` and used by `tests/wasm_runtime_test.rs` against the real engine. Runtime API 0.2.0 provides every capability in the v1 vocabulary: `library.read`/`library.paths` (windowed pages, path only with the second), `storage` (5 MiB, byte-accounted), `player.read`/`player.control` (observation and bounded transport, through a `PlayerBridge` the shell installs after its player thread spawns), `playlists.read`/`playlists.write` (host-validated ids; no delete in v1), and `network.http` (HTTPS to approved domains, one guarded resolver doing the single DNS lookup so a name cannot resolve public for the check and private for the connect). Components also export five coalesced event handlers beyond `on-settings-changed`. `RUNTIME_SUPPORTED` stays as the mechanism that keeps a package naming a future capability from loading against a host that would ignore it.

**Icons** (`src/lib/components/common/Icon.svelte` + `src/lib/icons.ts`): UI glyphs are inline **Lucide** SVGs (ISC-licensed), not the old Eole PNG sprites. `icons.ts` is **hand-maintained** (no generator) and holds two maps: `iconMap` (Eole glyph name → icon name, e.g. `"prev" → "skip-back"`) and `lucideIcons` (icon name → inner SVG markup, a 24×24 viewBox with no `<svg>` wrapper). `Icon.svelte` takes an Eole *or* Lucide name and renders it at `stroke-width 1.5` with `stroke="currentColor"`, so **color and hover come from CSS `color`, not opacity** (`SpriteButton` brightens on hover; the shuffle toggle stays full-opacity and signals state by *shape*, while repeat still dims when off). *To add/change an icon*: paste the target Lucide icon's inner paths into `lucideIcons` and point the Eole name at it in `iconMap` — that's it. A few icons are **custom composites** built from Lucide primitives: `rotate-cw-1` (repeat-one = rotate-cw ring + Lucide's repeat-1 "1"), `two-arrows-right` (shuffle-off = arrow-right-left with the bottom arrow mirrored right), and `volume-1..4` — a 4-wave fan (speaker path + N concentric arcs, center x≈10.5, half-angle 37°, radii 4/7/10/13 for 1→4 waves) that **overrides official Lucide `volume-1`/`-2`** so all four levels share geometry. Only two Eole PNGs remain in `static/eole/` — the `no_cover` and `nothing_played` placeholders (kept deliberately); everything else there was deleted.

## Gotchas

- **Tauri capabilities**: webview-side APIs (dialogs, `window.close()`, …) silently no-op unless allowed in `src-tauri/capabilities/`, and each window label must be listed there. If a frontend API "does nothing", check these files first — it has bitten twice (m3u file picker, cover-window Esc). **`#[tauri::command]`s are gated the same way** since `build.rs` declares an `AppManifest::commands` list: a new command needs its name in that list *and* an `allow-<kebab-case-name>` entry in the capability of every window that calls it, or the call is rejected at runtime ("not allowed by ACL", visible in the webview console, not the Rust log). Three capabilities split the windows: `default.json` (core APIs + close, all three windows), `main.json` (every command except the About window's three), `about.json` (`about_info`, `update_check`, `update_install`, and opening the repository URL). The cover window deliberately gets no commands. `src-tauri/permissions/autogenerated/` is regenerated by the build — commit it, don't edit it.
- **NVIDIA blank window**: `WEBKIT_DISABLE_DMABUF_RENDERER=1` is set in `src-tauri/src/main.rs`; removing it makes the window render black on this machine.
- Tauri command args: snake_case parameter names in Rust, camelCase keys from JS (`album_id` ↔ `albumId`) — Tauri converts automatically.
- AppImage bundling fails at linuxdeploy's GStreamer step; bundle targets are intentionally restricted to `deb` + `rpm` in `tauri.conf.json`.
- `reference/` is excluded from Vite's watcher (see `vite.config.js`) and is not part of the build — it is documentation. It is also **gitignored**: the bundled Eole theme carries no license, so never commit or redistribute it. The built `.deb`/`.rpm` still embed the two Eole placeholder PNGs (`no_cover`, `nothing_played`) — swap those before any *public* release.
- `CHANGELOG.md` is **intentionally gitignored** (local-only, never committed): it tracks changes between releases, grouped under version headers. When you land a user-facing change, add a concise bullet under `## Unreleased` in the same style as the existing entries. The `## Unreleased` section becomes the GitHub release description text for the next version bump — write bullets accordingly.
